# LearnIQ security review

Review date: 2026-10-11. This is a source review and local unit-test report, not a penetration test, cloud configuration review, or live Qdrant/Gemini integration test. Severity reflects this prototype; do not expose it publicly until the residual deployment and AI abuse risks are addressed.

| ID | Category | Severity and status | Evidence, remediation, and verification |
|---|---|---|---|
| 1 | SQL injection | Low, parameterized | SQLite uses prepared statements with bound parameters in `server/services/dataStore.js`; queries use fixed identifiers. Account/progress tests exercise the data layer. Dedicated malicious-input SQL regression cases were not added. |
| 2 | XSS | Low, mitigated; browser verification pending | React renders API text as text; the PPTX HTML preview escapes `& < > " '` and sets a restrictive CSP. Source search found no `dangerouslySetInnerHTML`. No browser payload test was run. |
| 3 | CSRF | Medium, mitigated | Session cookies are `HttpOnly; SameSite=Strict`; browser mutation requests with an Origin header are checked against `APP_ORIGINS`. Unit tests reject a disallowed origin. Requests without Origin remain possible for non-browser clients and still require session auth for protected actions. No live browser CSRF test. |
| 4 | Unsafe uploads | Medium, mitigated with residual parser/provider risk | Uploads are limited to one PDF/PPTX (20 MB) or MP4/MOV/WebM (100 MB); extension/MIME and file signatures are checked. PDF processing is limited to 500 pages/1,000 chunks; video transcription is capped at 1,200 indexed chunks and 24-hour timestamps. PPTX ZIP processing limits entries/decompressed size and never writes archive paths. PDF/PPTX visual inputs are also sent to Gemini; provider parsing behavior was not live-verified. Original files are retained privately, temporary Gemini file deletion is attempted, and partial Qdrant indexes are deleted on failure. No hostile media corpus/fuzzing test. |
| 5 | IDOR / object authorization | Medium, mitigated for new data; live-store verification pending | Scrypt-backed accounts and server sessions are required on document, RAG, quiz, and progress routes. SQLite document access/list/delete is scoped by owner. Tests cover cross-user SQLite lookup and session/quiz ownership. No live Qdrant test was possible; test helper verifies mandatory owner filters. Existing Qdrant points without owner metadata are hidden and must be re-uploaded under an account. |
| 6 | Rate limiting | Medium, partly mitigated | Per-IP/per-process limits protect auth (10/min), upload (5/min), RAG (20/min), and quizzes (10/min). Unit tests verify allowed and rejected counts. Limits reset on restart, are not shared across instances, and need deployment-aware proxy configuration. |
| 7 | JWT secrets | N/A | JWT is not used. Random opaque session tokens are stored server-side by SHA-256 hash. |
| 8 | Exposed API secrets | High impact if leaked; rotation outstanding | Gemini/Qdrant keys are read server-side from environment variables. `server/.env` is ignored and not tracked; `server/.env.example` and root `.env.example` contain placeholders. A credential-like token was included in the IDE selection in this chat; treat it as exposed and rotate it with its issuing provider, then update the local `.env`. I cannot rotate it without provider access. Git history and host configuration were not audited. |
| 9 | Weak password hashing | Low, mitigated | Accounts use per-user random salts and Node `scrypt` (N=16384, r=8, p=1, 64-byte output); comparison is constant-time. Unit test confirms stored hash is not plaintext. No password reset or credential-stuffing detection exists. |
| 10 | MFA | Not implemented | There is no MFA. It is not a PDF product requirement, but remains a risk for accounts holding private study documents if deployed beyond a controlled demo. |
| 11 | CORS | Low for same-origin deployment; deployment unverified | No permissive CORS middleware is configured. Vite proxies API endpoints, and browser mutations use an explicit Origin allowlist. Production hosting must set `APP_ORIGINS` to exact trusted origins and keep the UI/API same-site; no deployed host was reviewed. |
| 12 | Browser token storage | Low, mitigated | Session token is an HTTP-only, SameSite cookie, marked Secure in production; only its hash is stored in SQLite. Frontend does not use localStorage for tokens. Cookie behavior was unit-checked for attributes, not browser-tested. |
| 13 | Client-side-only permissions | Low, mitigated for covered routes | The backend resolves the cookie session and applies auth middleware to upload/library/source/delete, RAG, quiz, and progress routes. Frontend guards are not relied on. Route-level HTTP integration tests against a running server remain outstanding. |
| 14 | Row-level security / equivalent isolation | Medium, partly verified | SQLite records have user IDs and parameterized owner predicates. Qdrant query and delete filters always include `ownerId`; document-scoped assessments add a document filter. Unit tests cover filter construction and data-store isolation, but no live multi-user Qdrant test was possible. Legacy unowned points are not migrated. |
| 15 | Webhook signatures | N/A | No webhook endpoints exist. |
| 16 | SSRF | N/A for current feature set | The server does not fetch user-supplied URLs. Source navigation uses document IDs resolved from the owner's SQLite rows. Reassess before adding URL import or remote media fetch. |
| 17 | Production source maps | Low, deployment unverified | Vite config does not enable production source maps; Vite defaults them off. The production build passed when run outside the restricted sandbox; emitted assets had no source-map files. Hosting behavior was not inspected. |
| 18 | Default credentials | Low, mitigated | Prefilled demo login credentials and the fake login screen were removed. Account creation is explicit; there is no default backend account. Frontend source search performed. |
| 19 | Sensitive logging | Low, mitigated with residual diagnostics | Raw chat questions, AI answers, and provider error bodies are not logged by the RAG route. Development retrieval logs include source IDs, scores, counts, and previews capped at 120 characters; production omits previews. Other PDF/PPTX processing paths still log error messages. Runtime logs were not captured. |
| 20 | Vulnerable dependencies | Unverified | A root `npm audit --omit=dev --json` attempt failed to reach `registry.npmjs.org` and could not write a log in the restricted npm cache directory. No vulnerability conclusion can be drawn. Re-run the full audit with registry access; frontend package manifests/lockfile had pre-existing user changes and were preserved. |

## Verification limits

`npm test` passes 61 tests, including owner-scoped SQLite, Qdrant SDK request/index serialization, index initialization and filters, malformed/oversized upload rejection, per-chunk topic evidence, assessment lifecycle, and secret-file ignore checks. `npx tsc --noEmit -p Front-End/tsconfig.json`, all server JavaScript syntax checks, and `git diff --check` pass; `npm run build` passes outside the restricted sandbox. A deterministic simulation exercised real assessment/store code across three isolated profiles. No provider probe was made because credential rotation is not confirmed by the owner. No live Gemini/Qdrant requests, browser tests, or dependency audit results were produced. Existing user changes were preserved.
